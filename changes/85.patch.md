The fast tier computes on one thread on PyTorch (`tests/conftest.py`), as the xdist workers of the full tier already do. Since the fast tier runs in a single process, PyTorch started one compute thread per core, and on Linux its idle threads spin between two operations: the CPU time that the per-test budget measures counted them, and a spec parity case of T2.6 (`test_small_case_equals_the_oracle[2d-periodic]`) measured 1.07 s of CPU for 0.34 s of wall time on CI, over the 1 s budget, on the first pull request that ran the fast tier in one process. The tests of the fast tier run on data too small for threads to help. No test, statistic, public name or reference value changes.

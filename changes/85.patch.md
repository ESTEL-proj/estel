The tests give NumPy's linear algebra one thread (`OPENBLAS_NUM_THREADS=1`, set by `tests/conftest.py` before NumPy is imported, unless it is already set). On Linux the idle threads of OpenBLAS spin between two calls, and the CPU time that the per-test budget measures counted them: a spec parity case of T2.6 (`test_small_case_equals_the_oracle[2d-periodic]`), whose oracle is NumPy, measured 1.0 to 1.1 s of CPU for 0.34 s of wall time on CI, over the 1 s budget of the fast tier. The tests run on arrays too small for threads to help. No test, statistic, public name or reference value changes.

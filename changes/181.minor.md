`STOperator` on HEALPix data (task T5.6, issue #167; maths.md §4 "Scattering loop", M-DEF-HPX): the statistics mean, var and S1 to S4 of a `DataHealpix`, on the full sky or the partial sky of `cell_ids`, with or without a mask, through the loop, the normalisation, the reductions and the flattening of section 1; every option behaves as on 1D and 2D data, with the defaults of M-DEF-HPX (J = max(1, depth − 1), L = 4). They equal STL `HealpixUpdate`'s fixtures on the full skies and the oracle on the partial skies (OP-110). On HEALPix data the power spectrum is left out. On any data that are not 2D, `compute_PS=True`, `n_bins`, `Jmin`, `spectrum_method` and `SpectrumOperator` raise one message, the same for every geometry, which names the class received, LF23 (1D data, tensor products) and LF24 (HEALPix data); the code tests only whether the data are 2D, by their declared tag, not by `ndim`. `STOperator` given a `DataTensorProd` raises its "use STOperatorTensorProd" error before any check of the spectrum. `apply` refuses another partial sky of the same size (the plan compares `depth` and `cell_ids`), and the OP-3 messages have one advice for every geometry. Files: schema version 8 stores the static metadata of the data (`depth`, and `cell_ids` on a partial sky), so that `STStatistics.load` then `STOperator.from_statistics` rebuild the operator; files of version 7 are refused. No public name added; 1D, 2D and tensor-product values do not change.

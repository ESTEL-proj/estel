Periodic planar syntheses with checkpoints (task T6.1, #28; Part II, §12.9; maths.md section 5). New public names `estel.synthesize_from_maps`, `estel.synthesize_from_stats` and `estel.SynthesisResult` (`field`, `losses`, `n_iter`, `n_evals`, `converged`, `checkpoints`, `manifest`). They reproduce STL's syntheses: the Nyquist pre-filter, the standardisation of the target with `mean_field`, the Gaussian start (drawn with an explicit `seed`, OP-55), the loss on the complex form of the flattened statistics with the weights 3.5 and 3.5² of S3 and S4 (internal `STStatistics._to_complex_vector`, with `keep_batch_dim` and `mean_along_batch`, compared with the oracle's `spec_flatten`), STL's L-BFGS settings (step 1.0, 50 correction pairs by decision of the maintainer, strong Wolfe, tolerances 1e-12 and 1e-15, ⌊5 max_iter / 4⌋ evaluations) and STL's axes of the result (OP-75); `st_kwargs` takes `J` only, as STL's user level (M-SYN-OPS). Periodic fields without missing values only (LF47), on the PyTorch backend only (LF1); the power spectrum joins the loss with T4.1, so `compute_PS=False` is needed until then. Checkpoints (`checkpoint_every`, `checkpoint_dir`, `resume_from`) save the field, the optimizer state and the seed; a resumed run continues the same trajectory, bit for bit. The `lbfgs` contract of `Backend` is no longer provisional (decision 4): its settings default to STL's, it takes `lr` and `max_eval`, returns `n_evals` and `converged` (a stop on a tolerance; resuming a converged run does not iterate), and its state is NumPy arrays and Python scalars that a checkpoint saves. New parity fixture `synthesis_2d` (STL `master`): a 64 × 64 synthesis follows STL's loss over 20 iterations, with the same counts, within a relative 1e-10 (measured gap at most 1.0e-15), and ends on STL's field within the parity tolerance, in the full tier. The start is checked against M-SYN-INIT and M-SYN-NYQ (shape, keys, initial field, unit white noise, modes outside the disc set to 0, variance the fraction of modes kept; the pre-filter against its definition), and the start, a resumed field and the running field of `synthesize_from_stats` are on the device of the data or statistics. `synthesize_from_stats` refuses up front an `n_batch` that statistics computed without `ref_batch_mean` cannot normalise. Section 5 of `docs/maths.md` has no oracle, by decision of the maintainer (Part IV, §22, "No oracle for the syntheses"; edits authorised in `docs/maths.md`, Part I §5.1 and Part IV §22): `tools/check_maths_ids.py` moves it from the sections not yet implemented to a new list of sections without an oracle by decision, whose IDs need a test and no `_spec` function. No reference value changes.

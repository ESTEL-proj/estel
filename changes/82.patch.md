The oracle `estel._spec` exists for planar data (task T2.6): `src/estel/_spec/planar.py` transcribes sections 1 (planar 2D) and 2 (1D) of `docs/maths.md` in NumPy float64, every `M-` ID there except M-PS-2D, which comes with T4.1. The spec parity tests of `tests/spec/` compare ESTEL with it in float64, with the comparison helpers and tolerances of Part II, §14.3: the fast tier runs one small case per geometry and periodicity (2D and 1D, with a mask, J = 2), the full tier the matrix of Part I, §5.1; `make test-spec` runs them alone (`SPEC_TIER=full` for the matrix). `tools/check_maths_ids.py` no longer has `--allow-unimplemented`: it checks that every ID has an oracle function and a test, except those of an explicit list (sections 3 to 5 of `docs/maths.md`, and M-PS-2D), which the tasks that implement them shorten. ESTEL and the oracle agree on every case, so no statistic, public name or reference value changes.

One operator for every normalisation, as in STL (task T2.19, issue #192; Part IV, §22, "One operator for every normalisation"). The normalisation is chosen at each call of `apply`, everything else at construction:

- `STOperator(data, J, L, *, norm=..., ref_batch_mean=..., ...)` → `STOperator(data, J, L, ...)` then `op.apply(data, ref=None, *, norm="self", ref_batch_mean=False)`; the same for `STOperatorTensorProd`, and `estel.functional.scattering(data, plan, filters, ref=None, *, norm="self", ref_batch_mean=False)`. STL's `store_ref` then `load_ref` is one operator: `op.apply(target)` then `op.apply(other, norm="ref")`, which uses the reference the first call stored.
- `standardize` is True by default on both operators (STL: False; maths OP-120): `mean` is 0 and `var` 1 up to rounding, the spectrum is that of the standardised field, and a map of zero variance has NaN statistics. Pass `standardize=False` for STL's values.
- `ref` with `norm="self"` or `"none"`, `ref_batch_mean=True` with another `norm` than `"self"`, and `norm="ref"` without a reference raise clear errors; `norm="none"` stores and reads no reference.
- `STOperator.norm` is removed: an operator no longer has one normalisation. The statistics record the `norm` and `ref_batch_mean` they were computed with.
- The warning of a channel without auto statistics (OP-30) comes with a normalised call of `apply`, no longer at construction.
- Files: schema version 10, with the normalisation in the statistics instead of the plan; files of version 9 are refused. Synthesis checkpoints are unchanged.

The syntheses use one operator when the running field has the target's shape, with unchanged values.

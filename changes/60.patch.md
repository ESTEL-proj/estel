Register DataClasses as pytrees (task T2.9, Part I §3.1 rule 9): a new L0 primitive, `register_pytree(cls, flatten, unflatten)`, registers a class with `jax.tree_util` on JAX and with `torch.utils._pytree` on PyTorch (imported when called, falling back to its older `_register_pytree_node`; if neither exists, ESTEL only warns, since nothing in ESTEL needs pytrees on PyTorch, while on JAX any registration error is raised). Every DataClass geometry is registered when it is defined, on every backend, with the array as its only leaf, so `jax.jit` and `jax.vmap` accept a `Data1D` or `Data2D` and return one. The mask now enters the static part of the pytree through a read-only, hashable wrapper compared by value, whose hash is computed once, so that equal masks share one compiled function. The PyTorch behaviour is unchanged. No public name or reference value changes.

Add the backend registry and the global configuration (T1.5). Five new public names: `estel.set_backend(name)` and `estel.get_backend()` choose the default backend, `"torch"` by default or, experimental, `"jax"`, which warns at every call. `estel.set_default_dtype("float32" | "float64")` sets the default dtype; float64 switches JAX's 64-bit mode on, and raises `RuntimeError` if JAX already ran in float32. `estel.set_default_device("cpu" | "cuda" | "cuda:N")` sets the default device. Until it is set, the device is CUDA if available, else CPU, as in STL. `estel.BackendMismatchError`, a `TypeError`, is raised when arrays of two backends are mixed. The code is in `src/estel/backend/_registry.py` and `src/estel/_config.py`, and the tests are in `tests/api/test_config.py`. Part II, §12.2 records these signatures, as the maintainer asked on issue #39. No reference value changes.

## Goal

Each batch element can have its own mask of missing values, given or detected from the NaN of batched data, in planar 2D, 1D and HEALPix data (tensor products: LF8).

## Inputs

maths M-DATA-2D, M-DATA-1D and M-DATA-HEALPIX ("Missing data"), M-MASK, M-DOWN-MASK, M-MEAN, M-MASK-HEALPIX, M-PS-2D (`nan_mask`: observed "in every batch element and channel"); OP-26 (§1.11); Part I §2.3 ("Masks are static"); the card LF42 (masks per channel).
Modules: `src/estel/data/_base.py` (`_validate_mask`), `src/estel/data/_masks.py`, `src/estel/scattering/_plan.py` and `_loop_single_domain.py` (the weights), `estel/spectra/_estimators.py`, `src/estel/_spec/`, `tests/geometry/`.

## Tasks

1. [human] `docs/maths.md`: the mask is one map, or one per batch element, of shape `(Nb, …)`; the weights, the downsampled masks and the observed set of `nan_mask` per element; OP-26 closed. The accepted mask shapes in `api/manifest.json` if the entry of `Data` records them.
2. The oracle `_spec` with masks per batch element; then `Data`: masks of shape `(Nb, …)` accepted and detected from batched NaN; NaN that differ between the channels of one element raise an error naming LF42.
3. The plan, the loop and the spectra with weights per batch element; `changes/<PR>.minor.md`.

## Done when

On 2 × 16 × 16 data with NaN at different places in each element, the mask `(2, 16, 16)` is detected, and each element's statistics and spectra equal those of that element alone (planar 2D, 1D, HEALPix); a shared mask gives the 1.0.0 values (the reference tests pass without regeneration); NaN that differ between channels raise an error naming LF42; the differentiation tests with masks per element pass on both backends.

## Feature

Masks per batch element, and the mask detected on batched data

## Why

one 2D mask is shared by every batch element and channel, and its detection fails on batched examples (OP-26); masks per channel are LF42

## Builds on (reserved in 1.0.0)

masks as weights

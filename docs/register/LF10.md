## Goal

The power spectrum of 1D and tensor-product data: the spectrum of `STOperator` (`compute_PS`, `Jmin`, `spectrum_method`) on these data, with binned spectra, joint and low-pass bins, the reserved `spectrum_method=` names no longer raising (Part II §9.4); the four v1.6.0 estimators and `spectrum_method="auto"` on the axes of each block (§20.5), so that every planar geometry has spectra of non-periodic data and of data with missing values. `compute_PS` is True by default on these data, as on 2D data. LF23 (1D and tensor-product spectra) is merged into this entry.

## Decisions

- 25 November 2026, Pablo Richard: generalised directly, one piece of work (question 1, answer (a)); LF23 is merged into this entry, and its card removed; the row of the decision log keeps every citation of LF23 valid. This entry takes LF23's goal: `SpectrumOperator` and `compute_PS` on 1D and tensor-product data, joint and low-pass bins, the reserved `method=` names no longer raising (Part II §9.4). The pull request compares once with STL's `2D+1D` spectra, on periodic data without missing values, through the `2d1d` environment of the parity container, and keeps no parity test. The reason, corrected: the spectra of `2D+1D` are described nowhere in the specification and have no parity fixtures, so the two-step order would start by extracting them from STL's code; and no behaviour of STL is kept (the row "Versions" of 20 November 2026 in the decision log of the register) (`docs/register/decisions.md`).
- 25 November 2026, Pablo Richard: periodicity per block (question 2, answer (a)): borders are cropped only along the non-periodic blocks, and `method="auto"` picks `pbc_mask` when any block is non-periodic. The reason, corrected: `pbc_mask` keeps every Fourier mode in both options, its band maps being inverse FFTs of the whole plane; (b) would lose border pixels along the periodic blocks (`docs/register/decisions.md`).
- 25 November 2026, Pablo Richard: the NaN-aware estimators on tensor products (question 3): LF8 moves to step 2a, phase 2a.3. This entry keeps `nan_mask` and `pbc_nan_mask` on tensor products, and depends on LF8 (`docs/register/decisions.md`).
- 25 November 2026, Pablo Richard: `compute_PS` is True by default on 1D and tensor-product data, as on 2D data (and as STL on 1D data, M-DATA-1D, "Spectrum"). Pablo Richard will clarify golden rule 11 ("a new capability enters as an opt-in feature") in a separate pull request. The public names this needs, `lowpass="PS"` and `("ST", "PS")` and the spectrum options of `STOperatorTensorProd`, enter `api/manifest.json` with this entry (task 3) (`docs/register/decisions.md`).

## Done when

On 1D data of 32 points and on tensor products whose blocks have at least 16 points each (for example 16 × 16 × 16: with M-PS-2D's range read per block, an 8-point block gives N\_max = 4 and J\_PS = 1 < 2, which OP-93 refuses), each estimator matches the oracle in float64; `spectrum_method="auto"` follows the table of M-PS-2D, read per question 2; `compute_PS` is True by default on 1D and tensor-product data, and the reserved `method=` names no longer raise there; the comparison with STL's `2D+1D` is reported in the pull request; 2D spectra unchanged (the reference tests pass without regeneration); the second-order and JAX tests pass on the new spectra.

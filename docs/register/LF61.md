## Goal

`SpectrumOperator` accepts odd sizes with every estimator: the band-pass estimators give the original sizes to the inverse FFT (OP-20).

## Inputs

maths M-PS-2D, "Band maps" and "Frequencies and bins" (N\_k: the rFFT columns counted twice); OP-20 (§1.11); Part IV §22, "Spectra on odd sizes" (18 November 2026); Part II §12.3 (the `fft` extension of `xp`), §12.8.
Modules: `estel/spectra/` (`SpectrumOperator`, `_estimators.py`), the spectra of `src/estel/_spec/`, the tests of the spectra.

## Tasks

1. [human] `docs/maths.md`: the band maps of M-PS-2D take the original sizes, and for an odd width the last rFFT column, which is not a Nyquist column, is counted twice in N\_k; OP-20 closed.
2. The oracle on odd sizes, then the operator: the inverse FFT given the original sizes (`irfftn` with `s=`), the even-size error removed; `changes/<PR>.minor.md`.

## Done when

Every estimator accepts 15 × 17 and 16 × 17 data and matches the oracle in float64; a band map has the shape of its data; even sizes keep their values (the reference tests pass without regeneration). If the `fft` estimator already accepts odd sizes in 1.0.0 and its values there change, stop: that is a change of values (golden rule 1); open an issue.

## Feature

Spectra on odd sizes: with band-pass filtering, the original dimensions passed to the inverse FFT (`irfft`)

## Why

the even-size constraint comes only from spectra with band-pass filtering, whose inverse FFT loses the original width; given explicitly, the Spectrum operator supports even and odd sizes (OP-20)

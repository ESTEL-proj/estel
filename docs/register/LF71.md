## Feature

The normalisation reference is an explicit object that the user passes, instead of a reference that `norm="self"` stores in the operator as a side effect

## Why

in 1.0.0, as in STL (`store_ref`), `norm="self"` normalises the statistics by themselves and also stores that reference in the operator, replacing the previous one (maths M-NORM); a later call with `norm="ref"` then depends on which call with `norm="self"` came last: hidden state in the operator. The maintainer's reservation: a reference computed from data is itself a full scattering computation, which an explicit normalisation should not hide either

## Builds on (reserved in 1.0.0)

the reference carried by the statistics (`STStatistics`); one operator for every normalisation, `norm` and `ref_batch_mean` chosen at the call (the change of the API decided for step 1 on 25 November 2026)

## To decide

the form of an explicit reference (statistics passed to the call only, or a reference object of its own); whether `norm="self"` keeps storing its reference; whether building a reference computes scattering statistics or takes them from statistics already computed

## Details

maths M-NORM; Part I, §2.3; Part II, §12.6. Suggested step: 2a

## Source

decision of the maintainer Erwan Allys, 25 November 2026, with the decision that one operator serves every normalisation

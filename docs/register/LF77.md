## Feature

A synthesis whose running field differs from its target in what the static plan fixes, without building a second operator: another size (`running_shape`), or another periodicity (a target learned with `pbc=False`, a synthesis made with `pbc=True`). A study first, of whether the second operator costs anything that matters, then, if it does, a way for one operator to serve several sizes or periodicities

## Why

The size of the data and its periodicity (`pbc`, with the border crops it implies) are part of the static plan, fixed when the operator is built (Part I, §2.2.2): an operator refuses data that differ from those it was built for, and says to build a new one. One operator serves every normalisation (Part IV, §22, row of 25 November 2026), and a synthesis uses one operator only when the running field passes the target's plan: the same size, the same `pbc` and the same mask (T2.19, #192). There is therefore no simple way to synthesise at another size than the initial map, nor to learn a target with `pbc=False` and synthesise with `pbc=True`, without two operators, the running one receiving the target's reference. This is not necessarily a problem, but it is to be investigated; the maintainer asks Pablo Richard to look at it

## Builds on (reserved in 1.0.0)

`running_shape` of `synthesize_from_maps` and `synthesize_from_stats`, on 2D data (Part II, §12.9; maths M-SYN-OPS, OP-101); `apply(data, ref=…)`, through which the running operator receives the target's reference

## To decide

whether the second operator of a synthesis whose running field differs from its target in what the plan fixes (its size, its periodicity) is a problem: its build time and memory, the reference passed from one to the other; if it is, how one operator could serve several sizes or periodicities

## Details

In 1.0.0 the targets of syntheses are periodic and without missing values (LF47): a different periodicity arises once LF47 accepts non-periodic targets, a different size already with `running_shape` on 2D data (refused on HEALPix, OP-101). What to measure first: the build time and the memory of the second operator against those of the synthesis itself, at the sizes of the benchmark; whether the reference of one size, or of one periodicity, is the right reference for the other (at equal J and number of bins the scales j and the bins of the spectrum are the same, M-SYN-OPS; the border crops of a non-periodic field change which pixels enter the means). Possible ways, if it matters: an operator that holds the plans of several sizes or periodicities; plans built lazily inside one operator; or keeping two operators, documented. Any of them must keep the rule of one operator per data (no cache shared between operators). Suggested step: 2a.4, with the syntheses and LF47

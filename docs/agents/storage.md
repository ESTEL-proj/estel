# Storage of data and statistics

Summary of [Part I, §2.3 — Object model](../transfer/part1.md#23-object-model) and [Part III, §19 — Compact coefficient layout](../transfer/part3.md#19-compact-coefficient-layout). The transfer document is authoritative.

## Data

- A `Data` object holds one array plus immutable geometry metadata (pbc, cell ids, block structure); it is a pytree whose only leaf is the array. Operations return new objects (`with_array`); nothing is modified in place, and there is no `conv_history`.
- **Masks** of missing data and their reweighting maps are computed once, at construction, and stored in the static plan; they reach the computation as constant weight arrays.

## Statistics: the compact layout (Part III, §19; task T2.15)

Principle: **compute on structured arrays, store in a flat compact buffer, never mix the two.** The conversion is a static gather whose indices are built in NumPy with the plan.

- **Two representations.** Compute: per level, structured arrays, inside `scattering()` only, no NaN (masks are weights). Storage: one real buffer `(B, n_floats)` in `STStatistics`, its only array leaf with those of the reference and the standardisation.
- **What is stored.** Every coefficient STL computes, and only those: no structural NaN, no mean without a valid pixel (M-MEAN, OP-3). Real entries take one float (mean, var, the auto S1 and S2, the diagonal of S4, every entry of PS); complex entries take two, (re, im). STL's conjugate duplicates are kept, without packing (Part III, §19.8, option a); the canonical set is LF20.
- **`Layout` and `Segment`** (`src/estel/statistics/_layout.py`, internal): frozen, hashable descriptions, usable as JAX static arguments. One segment per family and level, with its offset, stored by chunks: one chunk per channel pair and scale combination, holding the dense array of its orientations, which always exists in full. The layout keeps one small row per chunk, never a table per coefficient, and computes the coordinates of an entry on demand (T3.7). Within the buffer the families follow the order mean, var, S1 … S4, then the levels, then the order of the full grid.
- **The conversion** from the loop's sums to the buffer is written once, in shared Python on generic primitives (Part III, §19.9): `statistics._layout.loop_sums` gives the order of the loop's sums, each a chunk, `_layout.loop_gather` the static gather, chunk by chunk, which the loop applies once, at its end.
- **Normalisation, reductions and selection** (`iso`, `angular_fourier`, `scale_cosine`, `select`) are static linear maps on the buffer (Part III, §19.6): each is built in NumPy from the layout and acts chunk by chunk, on the orientations of each chunk or across chunks, with tables that grow with the number of chunks and of orientations, never with the number of coefficients (T3.7); it returns a new layout. They are differentiable to second order and backend-neutral.
- **Full-grid views** (`stats.full_grid("S4")`) keep STL's shapes and dtypes, NaN where no coefficient exists, the imaginary part 0 for the real entries. They are built on demand with `scatter_to_grid`, for humans, plots and comparisons with STL, and are never called inside `scattering()` (review rule X5; a test asserts it). Code outside `STStatistics` uses the accessors (`full_grid`, `select`, `to_vector`, `reduce`), never the buffer directly.
- **Files.** `estel.io` writes the buffer and the layout, by chunks, the statistics of tensor products with their blocks, J, L and low-pass flags (T3.6), and the power spectrum with its parameters, its estimator and its reference, and the statistics of `SpectrumOperator`, the family `"PS"` alone (schema version 7, T4.4, T4.1); files of version 6 are refused.
- **Power spectrum** (maths.md §1.9; T4.4). When the plan has it (`PlanarPlan.spectrum`), the family `"PS"` is the last segment of the buffer, after S4, at level 0: one chunk per channel pair c₁ ≤ c₂ of `cross_matrix`, holding the dense array of its n\_b bins (axes `c1, c2, bin`), every entry one float. The loop's gather writes the floats before it; the spectrum operator (T4.1) writes those of PS. The reference holds σᴾˢ compactly beside σ (`_NormReference.sigma_ps`, with the channels and the parameters `{n_bins, J, Jmin}` of the spectrum); the reductions copy PS unchanged.
- **Tensor products.** Their segments, with their multi-index levels, are built from the per-block index sets (maths M-IDX-TP), never from an array the size of the full grid (T3.6): `scattering._plan.TensorProdPlan`, `_grid.tensor_prod_grids`, `_layout.tensor_prod_layout`. A chunk of S1 or S2 at a low-pass scale of a block holds orientation 0 only along that block (M-LP): each kind of chunk has its orientation shape (`FamilyGrid.shapes`), each segment keeps one, and the maps act on one shape at a time (`FamilyGrid.shape_groups`). `full_grid` refuses a view over 2 GiB, `select` takes `family` and the channels only (LF44), and `reduce` raises (OP-44, LF26). `statistics._statistics.tensor_prod_statistics` normalises a raw buffer as its plan says; the loop of T3.2 writes into that buffer.
- **Later.** Packing the conjugate duplicates comes with the canonical set (LF20).
